## 2. 步骤 3:调研与引用

- **爆炸碎片 = 从爆点**持位**→ 向外点力散开 → 静置 → 被吸引子接管**(时序靠曲线/外部
  时间参数控制):Unreal Niagara 社区的标准做法(先按住原点,再用 Point Force 从**撞击点**
  向外散开,时序用 Curve 驱动),与社区爆炸-吸入两段式一致。
  <https://unreal2.epic-prod-us2.discourse.cloud/t/niagar-needs-your-help/2469583>
  → **取用**:散开方向取**绕源滴均匀**(局部量),而非域心径向;凝滞用**进程窗**(位移保持、
  吸引子未启动),不引新通道(与上轮「先炸开再吸入」同一数学形态,只把外推换成局部散射)。
- **画面过曝/惨白:先动色彩管理(tonemapping/exposure),不要先动材质(albedo)** ——
  社区通行口径:过曝的典型成因是 HDR 场景直接落进显示域,高光糊成白、中间调压平;
  修法是**调 tonemap 与曝光**,必要时再动 whitePoint/对比;albedo 不是首选杠杆。
  <https://runebook.dev/en/docs/qt/qml-qtquick3d-helpers-extendedsceneenvironment/tonemapMode>
  <https://runebook.dev/en/docs/qt/qml-qtquick3d-helpers-extendedsceneenvironment/whitePoint>
  → **与本轮实测互证**:正午的池底反照率(材质侧)几乎无效(见 §4 消融表),
  **曝光才是杠杆** —— 正好落在「先动曝光」这条社区口径上。

## 3. 方案 A:炸裂分散到四周 + 凝滞一瞬

**运动模型**(`fxdriver.convergePoint`,三段,逐点确定性):

```
p     = span01(t, t0, t1)                        // 各自飞行窗
炸裂   out = easeOutCubic(span01(p, 0, 0.20))      // 位移量 0→1 快出
凝滞   [0.20, 0.46]                                // out=1、back=0:位移保持、漩涡未启动
吸入   back = easeInCubic(span01(p, 0.46, 1)); inp = span01(p, 0.46, 1)
       local = POINT_BURST_R·k_i·(out − back)      // 局部量(相对**源滴**)
       x = C + cosθ·r_vortex + cos(bang_i)·local   // bang_i:绕滴心均匀 → 四周
       θ = θ0 + 3.4·inp^1.7 ,  r_vortex = r0·(1 − easeInCubic(inp))
```

- `POINT_BURST_R = 0.032`、`k_i ∈ [0.6, 1.4]` → 炸开半径 0.019–0.045(≈1–3 倍滴径);
- **凝滞窗占比 0.26 × 飞行(~0.7–0.9s) ≈ 0.2s**,窗内只有 `POINT_HOLD_JIT = 0.0008` 微颤
  (「时空静止不是死帧」,与爆散段悬停同一口径);
- 悬浮/飘散、尺寸、出现快闪等上一轮口径**不变**;爆散段与巨滴时间线**不动**。

## 4. 方案 B:正午水面降亮(诊断 → 标定)

### 4.1 诊断(逐项消融,同机位同参数,取水面区 [700,260,1180,520] 整帧均值)

| 消融项(正午置零/减半) | 水面区均值 | 结论 |
| --- | --- | --- |
| 基线 | **192.92** | — |
| 太阳强度 → 0 | 167.80(−13.0%) | **主杠杆** |
| 池底边缘提亮 `bottomEdgeLift` → 0 | 185.84(−3.7%) | 次要(且它压蓝度,是「洗白」来源) |
| 曝光 → 0.4 | 183.75(−4.8%) | 杠杆被 ACES 肩部压缩 |
| 水面色调混合量 → 0 / 焦散 → 0 / 镜面 → 0 / 池底反照率 −50% / 天空色 → 红 | ±1% 内 | 单项几乎无效 |

- **层归属验证**:把水面着色器强制成红色/深灰(alpha=1)→ 画面显著变化 ✔;
  把水面 alpha 置 0 → **画面不变** ⇒ 正午看到的「水面」其实是**池底平面**
  (`LUX_BOTTOM_FRAG`:`uBottomAlbedo×2.15` × 光照 + 焦散 + 边缘提亮);
  把池底片元强制成红 → 区域变红 ✔。
- **结论**:正午场景 HDR 整体压在 **ACES 肩部**(高光饱和)→ 任何单项参数杠杆都在 ±1–13%;
  要「读出结构、不惨白」必须**把整体曝光拉回中间调**(与 §2 社区口径一致)。

### 4.2 标定(量—调—再量,四项组合)

| 项 | 前 | 后 | 说明 |
| --- | --- | --- | --- |
| `exposure` | 1.0 | **0.5** | 主刀:把过曝 HDR 拉回中间调 |
| `sunIntensity` | 3.3 | **2.75** | 仍全表最强(> 傍晚 2.4) |
| `causticScale` | 1.35 | **1.0** | 焦散是**加白光**,是「惨白」的加性来源;仍全表最强(> 傍晚 0.7) |
| `bottomAlbedo` | [0.1, 0.22, 0.42] | **[0.08, 0.19, 0.38]** | 蓝分量保留、红绿收紧 |
| `bottomEdgeLift` | 0.16 | **0.06** | 灰白池壁提亮;实测同时抬蓝度 |

**实测结果(改前 / 改后,同机位同参数)**:水面区均值 **192.92 → 179.88(−6.8%)**,
`rgb=(189.4,191.3,210.3) → (176.6,177.8,199.2)`;落入清晨/傍晚档(171 / 181)之间,
水底焦散结构可读、光点在正午可辨。
**其他时段零回归**:傍晚基线 **181.44 → 181.44(逐值一致)**;清晨/深夜未改预设。

## 7. 迭代记录

1. **「分散」两次修正**:初版把炸开写成「域心径向外推」→ 证据帧里光点被推离中心、
   不围着原滴(不满足「四周」)→ 改**局部位移 + 绕滴均匀方向**;单测守护方向铺开。
2. **凝滞判据取错**:初版单测拿「与源滴距离的峰值」当凝滞起点,而该峰值其实落在**抵达端**
   (终点离源滴 0.12)→ 断言失效;改为「存在连续静止窗」的直接度量。
3. **正午标定两轮**:单项候选(曝光 0.85/0.4、反照率、天空、背景、水色)逐项实测**均 ≤5%**
   → 判定「过曝在 ACES 肩部」→ 改**组合标定**(曝光为主)才拿到 −6.8%。
