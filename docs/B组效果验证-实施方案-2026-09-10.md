## 2. 三个必须先纠正的认知（本方案的核心）

### 2.1 「刀片感」的根因是亚像素，不是调色 —— 已知失败点的真正解释

上一版把液桥颈缩到 `0.055r`，读出来是一条又黑又扁的刀片。调研查明：**这首先是几何/像素问题**。

相机 `PerspectiveCamera(45, aspect, 0.01, 20)` @ `(0, 1.0, 1.4)`（`viewer.ts:495-501`），域尺度 1.0，`rMin/rMax = 0.01/0.028`。@900px 高：

| 半径 | 1px 对应世界长度 | 颈径 `0.05r`（`BRIDGE_NECK_FRAC`） | 端径 `0.30r`（`BRIDGE_END_FRAC`） |
| --- | --- | --- | --- |
| r=0.010 | 1.584e-3 | **0.63 px** | 3.8 px |
| r=0.018 | 1.584e-3 | **1.14 px** | 6.8 px |
| r=0.028 | 1.584e-3 | **1.77 px** | 10.6 px |

圆柱之所以读作圆柱，靠径向明暗带（高光带／亮面／明暗交界／反光）的**空间分离**；宽度降到 2px 以下这些带合并、被 MSAA 平均，只剩剪影——**调成什么颜色都只能读成薄片**。

**对策（几何侧，必改）**：颈径设**屏幕空间下限** `minNeckPx ≈ 2.5–3 px`（默认机位约 `1.6e-3` 世界单位 ≈ `rMax` 的 4.5%）。「极细」的**读法**改由**端/颈比**承担（端 3.8–10.6px vs 颈 2.5px → 1.5–4×），而不是绝对变细。

### 2.2 逐桥状态量只能走逐顶点属性

`viewer.ts` 的 `uniforms` 对象被 5 个材质共享（`surfaceMat / dropletMat / bridgeMat / bottomMat / mistMat`，见 `viewer.ts:203/211/221/229/240`）。所以**任何逐桥变化的状态量都不可能用 uniform 表达**——现有 `aFade`/`aEmph` 正是这个原因，这是唯一解而非风格选择。

### 2.3 「黯淡」不能靠压暗 —— 在亮背景下方向是反的

- **合成算术**：`C = C_src·a + C_bg·(1−a)`。背景是亮水色（近白浅蓝），液桥体色 `body = vec3(0.55,0.78,0.95) * lit * 1.5`（`luxShaders.ts:749`）本就与背景低对比；乘 0.45 后**亮度显著低于背景**，`|ΔL|` 被拉大 → **更抢眼**。「降低亮度 = 降低存在感」只在高对比暗背景上成立。
- **规格自相矛盾**：动效文档 §1.3 明写「关系再弱，液桥也不会细到肉眼无法分辨，情感的张力交由流速、水花颤动承载」——「变细」直接违反自家规格。
- **语义撞车**：动效文档 §2.3 规定**灰色 = 已退场/未出场**。所以「疏远」绝不能走灰/暗，否则与「死亡」撞语义。

**对策（观感四轴）**：

| 轴 | 做法 | 理由 |
| --- | --- | --- |
| ① 向**背景色**收敛，不向黑收敛 | `col = mix(col, uFadeTint, k)`，`uFadeTint` 取水面/天空色；Fresnel rim 项**豁免**混合 | 即 `applyMist`（`luxShaders.ts:537`）的空气透视；剪影保留＝「还连着」，内部塌陷＝「但淡了」 |
| ② 保亮度、去饱和 20–30%、色相留蓝 | 只在 chroma 轴退 | 均匀去色＋高明度对比＝「幽灵」；保色相＋低明度对比＝「将熄但还在」 |
| ③ 只动镜面、不动 albedo | roughness 0.14 → 0.28–0.35 | 高光变阔变钝＝湿感退成哑光。**绝不要 `gloss *= 0.45`**；且抬 roughness 是**降低** HDR 峰值的方向，与三次白爆整改同向 |
| ④ 速度是最便宜的活力轴 | 流速 ×0.15–0.25、去气泡、内部用噪声 dissolve | 静止＋暗＝死；**斑驳流失 ≠ 均匀淡化** |
| ⑤ **Rayleigh–Plateau 珠化** | 沿桥 `r *= 1 + A·sin(u·K + seed)`，`A≈0.15–0.25` | 真液柱断裂前的物理行为；比「整体变细」更像液体，且**始终连着**，与「拉伸不断裂」裁决完全兼容 |

## 3. 通用底座（三个属性）

桥几何是手搓漏斗管（`vertsPerBridge = 11×8 = 88`，`bridgeMax = 21`），**没有 UV**，所以先造轴向坐标。顶点布局静态（每帧只改 position），故：

| 属性 | 更新 | 内容 |
| --- | --- | --- |
| `aUV` (vec2) | **init 一次**，StaticDrawUsage | x = 段号/10（沿程），y = 环号/8（周向） |
| `aSeed` (float) | **init 一次** | 每桥随机相位 → **去同步（防整网同步白闪）** |
| `aState` (**vec4**) | 每帧 1 次 upload | 打包 `(reveal, flowSpeed, bubbleAmt, turb)` |

- 打包成一个 vec4 而非 4 个独立 buffer → 一次 `needsUpdate`、一次上传；21 桥 × 88 顶点 × 4 float ≈ 30 KB/帧，可忽略。
- 现有 `aEmph`/`aFade` 保持不动，新增通道并行。
- **铁律：不写 `if (state == 3)` 分支。** 五状态用**连续参数**表达，切换靠 `aState` 平滑过渡；硬分支会导致切换「啪」地跳变、无法交叉淡入。现有 `if (uNightDots > 0.5)` 是**全局**时段开关，性质不同，保留。
- CPU 侧已备好：轴向量 `u` 与正交基 `n1/n2` 建样条时就算好了；`pointerToWorld`（`viewer.ts:1105-1113`）与点到线段距离（`bridges.ts:262-281` `capsuleIntruded`）可直接复用。

## 4. 七个效果的实现路径

### 4.1 融合（双向缓慢流动 + ≤8 微气泡）

**程序化 + 单元量化**（不堆粒子）：

```glsl
float cell  = floor(vUv.x * 8.0);            // 沿轴切 8 格 → 硬性 ≤8 颗/桥
float local = fract(vUv.x * 8.0);
float rad   = 0.10 + 0.55 * pow(hash11(cell + 7.0), 4.0);   // 幂律：多小 + 少大
float pos   = 0.5 + 0.45 * sin(uTime * (0.4 + 0.6 * r) + r * 6.283);  // 格内往复
```

气泡远小于格宽 → `fract` 回绕天然不可见，**「数量硬上限」与「不闪不跳」同时成立**（阈值噪声做不到计数）。
**双向流动用相位往复**（`phase = vUv.x*6.0 - 1.2*sin(uTime*0.35)`），**不要**两层反向滚动（读作噪声）。
**气泡要「读起来是气泡」而非亮点**：用**减性暗体 + 贴边回升**（IQ *Bubbles* 的分水岭——加性亮环＝火花，减性暗体＝气泡）；顺带好处是不进 bloom。

- 规格「融合气泡 ≤8/桥」与业界惯例一致：RTVFX《Profiling Tips》"7ish is fine"；IQ 参考为整屏 40 颗，一座桥占屏面几个百分点折算约 2–4 颗。判据是「是否可数」与填充率，不是密度。
- 备选：实例化粒子沿样条 advection——仅在需要「气泡被液滴遮挡」时才上，代价是粒子池 + 透明队列新成员。

### 4.2 极限拉扯（**先做，因为它是已知失败点**）

见 §2.1（屏幕空间颈径下限）+ §2.3（观感四轴）+ Rayleigh–Plateau 珠化。
这一项**零新增几何、零新增粒子**，改的是几何下限与调色公式，做完即可对比上一版的「黑刀片」。

### 4.3 湍流（沸腾 + 水花飞溅）

- **主力：片元边缘噪声侵蚀**（相干位移读作「果冻蠕动」，**非相干**才读作「沸腾」）：
  ```glsl
  float rim = 1.0 - abs(dot(n, v));
  float e   = rim * (vnoise(vec2(vUv.x*40.0 - uTime*3.0, vUv.y*6.0)) * 0.7
                   + vnoise(vec2(vUv.x*13.0 + uTime*1.1, vUv.y*3.0)) * 0.3);
  float th  = 0.55 - uTurb * 0.35;
  alpha *= smoothstep(th, th + 0.08, e);        // 轮廓被噪声啃碎
  foam   = smoothstep(th + 0.08, th - 0.02, e); // 侵蚀前沿＝水沫带（不加会读成「材质被抠掉」）
  col   += min(foam * FOAM_COLOR, FOAM_CLAMP);  // 钳制
  ```
- **顶点位移（辅助）有前置条件**：桥只有 10 环 × 8 边，周向 8 顶点位移会读成多边形。要用就得先把 `BRIDGE_RAD` 提到 12–16、`BRIDGE_LEN` 提到 14–16（顶点数 ×2–3，总量仍 <7k，索引只 init 建一次）。位移必须带**两端归零掩码**（`sin(π·vUv.x)`），否则破坏「桥从液滴里长出来」的构造。
- **⚠ 飞溅粒子的工程约束**：弹坑池只有 `maxDroplets = 7` 槽，**满池退化为单步注入**（`engine.ts:135-150`，`CRATER_STEPS = 10` ≈ 67ms）。故飞溅**不能每帧多发生成**：每桥限流 ≥0.2–0.3s 一次、多个小落点**合并成一次** impact；坐标需世界→引擎域反变换（`+ half`）；volume 取**负值**（凹陷，与现有 hover 涟漪同号）。
- **液滴高频颤动**：物理态由引擎持有，**不得改物理**；只在 `LUX_DROPLET_VERT` 做纯视觉偏移，且必须同步偏移 `vCenter`（透镜采样基准来自 `instanceMatrix` 平移，`luxShaders.ts:624`），否则透镜与接触环错开。

### 4.4 暗流（单向冲刷）

密排格程序化短亮条，`fract` 回绕；**速度离散 2–3 档 + 尺寸幂律**。（单一速度会读成「传送带」。）
**所有层速度符号必须同向**——「无回流」是设计语义。亮条用**乘性/钳制**，不进 bloom。

### 4.5 潜流（搅动浮现）

**CPU 算指针-线段距离 → 逐桥 `reveal` 属性 → 片元 dissolve**（不要在 shader 里做样条距离场：桥轴就是两端锚点的线段，几乎笔直，且现成零件齐全）。
- 缓动**快进慢出**（进入 ~0.25s，退出 ~1.5–2.5s）→「被搅动后慢慢沉淀」。
- 三个「像泥沙而不像溶解」的细节：**① 方向性**（阈值沿世界 Y 由下往上推进）；**② 非对称缓动**；**③ 前沿色带**（dissolve 边缘辉光改成**沉积物色**，用参数倒序的反向 smoothstep）。
- `alpha < 0.004 → discard`（雾 shader 已有此写法），平时不占混合填充。

### 4.6 凝结登场

起雾（`COMMON_HELPERS` 已有 `vnoise`，雾噪声与现有 `LUX_MIST_FRAG` 同族）→ 聚拢（位置向目标插值 + 半径收缩，`easeInCubic` 制造「被吸进去」的加速感）→ 凝结（HDR 闪点，**必须钳制**）+ 液滴 scale 弹簧过冲 → **抽桥**。

**抽桥的省事解法**：桥是每帧重建的合并 geometry，已有逐顶点 `aFade`/`aEmph` 机制。**再加一个逐顶点 `aGrow`(0→1)** 即可实现逐桥抽出，**零新材质、零新 draw call**；按「距新滴远近」错峰 0.2–0.3s/桥。

**雾用池化 billboard（InstancedMesh，单 draw call、固定容量、`setDrawRange`）**，噪声直接照搬 `LUX_MIST_FRAG` 的双频团涌写法，共享 `uniforms` → **四时段配色免费继承**。数量：起雾团 8–16 个大 billboard 即可（域 1.0，滴径约 0.05）。

### 4.7 死亡蒸发

**三段式接力，只有最后一段碰透明度**：

1. **0–55% 沸腾**：顶点噪声抖动幅度 0→1（衰减 specular），rim 项向 HDR 提亮并 `min()` 钳制 → 借 bloom 出「边缘在烧」。**完全不动透明度，纪律零冲突。**
2. **50–90% 汽化**：液滴 scale ×(1→0.35) 同步上浮；**蒸汽粒子从球面采样点向上喷发**（初速 + 上升 + 横向 curl 扰动 + 渐变淡变大）；桥从外向里逐根触发（`aGrow` 反向）。
3. **85–100% 收尾**：残核用**抖动丢弃（hashed alpha discard）**在 ~0.25s 内溶掉。

**为什么必须用 discard 而不是 alpha 淡出**（本项目已裁决纪律的正面冲突）：液滴是**珍珠不透明 + `depthWrite=true`**。

- 保留 `depthWrite=true` 而 alpha→0 → **隐形球继续剔除身后的桥**，出现「桥凭空断一截」（正是第十一批二次整改刚修好的 bug 反向复现）；
- 改 `depthWrite=false` → 桥/雾叠画穿透球面（二次整改已修的问题）。
- `discard` 的片元**既不写颜色也不写深度**，任意进度下深度都正确，**不留洞**。three 官方 `alphahash_pars_fragment` 可整段移植（Wyman 2017 *Hashed Alpha Testing*，本地 `node_modules/three/src/renderers/shaders/ShaderChunk/` 可读）。

**桥的「断裂」怎么处理**：注意委托方既有裁决是**拉伸不断裂**，且新裁决要求**关系桥的存在性由数据决定**。所以死亡时桥的消失应表达为**沿 `aGrow` 反向回缩 + aFade 隐没**（数据说这段关系结束了），而**不是**「拉丝到极限啪地断开」——两者在观感上都要「断」，但机制完全不同，后者已被否决。

**原位残留雾气**：复用 4.6 的雾 billboard，反向（从中心散开、缓慢淡出，3–5s）。

## 5. 三条纪律的应对

### 5.1 HDR 项天然可钳制（防重蹈三次白闪）

1. **首选乘性而非加性**：`col *= 1.0 + min(detail, K)`——乘性项被基色约束，基色已被 `applyGrade`/`min()` 管住。
2. 加性项一律 `min(term, CONST)`，`CONST` 用具名常量（已有 `GLINT_CLAMP`、`causticClamp` 先例）。
3. 噪声**先 `saturate` 再乘**，绝不把无界噪声直接加进颜色。
4. **去同步（夜闪教训的直接推论）**：真因不是单项太亮，而是「网络内桥姿态相近 → 同时扫过月亮半向量」。**所有新的时间驱动项必须带每桥不同相位**（即 §3 的 `aSeed`）——否则即使每项都不爆，多桥叠加也会爆。
5. 可选治本升级：Filament 的 specular AA（按像素法线变化率抬 roughness），正对治「晃动时扫过半向量」。

### 5.2 透明队列

**所有逐桥内部细节（气泡/流动/侵蚀/浮现）合进同一个 bridge shader、同一个 draw call。**
- three.js 排序键是**物体原点投影深度**，不是逐三角形；拆 mesh 会直接错涂。
- ⚠ `bridgeMat` 是 `DoubleSide` + `transparent` → **双面透明会被拆成两次 draw**（先背面后正面）。所以桥**今天**每像素已被混合两次：有效 alpha = `1−(1−0.3)² ≈ 0.51`，不是 0.3。这解释了「调 `uBridgeOpacity` 手感总是不准」；再拆出「内部气泡管」会被混合 3–4 次，边缘必出双层密度暗带。
- OIT 不值得（少量手写排序的透明网格，收益 < 多一遍透明几何 + 双 MRT 带宽）。
- 若确要上实例化飞溅粒子：插在 `renderOrder` 10 与 11 之间、`depthWrite:false`，靠液滴 `depthWrite:true` 被正确遮挡（已有机制，可靠）。

### 5.3 测试纪律

工程已有「shader 源码字符串断言」测试（`luxNight.test.ts` / `luxDrop.test.ts` 逐条钉住 `min(...)` 与具体系数）。**新效果必须同步加断言**，至少钉住：每个新 HDR 项的 `min(`/`saturate`、每桥相位项存在、`aUV` 静态属性存在、颈径屏幕空间下限常量存在。

## 6. 取帧机制（步骤 6 的前提）

本机 Chrome 可 headless 跑 WebGL 并截图（**已实测**：`--headless=new --enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader --screenshot` 成功渲出清晨时段水面与雾气）。

但 `--virtual-time-budget=9000` **只推进到 `simTime 0.06`** ——仿真时间推不动，截不到想截的瞬间。故验证页必须做成 **URL 参数驱动取帧**：

```
/fxspike.html?fx=7&t=1.4&shot=1
  → 建场景 → 把仿真推进到 t=1.4s → 渲一帧 → 停住（不再渲染）
  → 之后任意时刻截图都能拿到这一帧
```

每效果取三类帧：**中景 / 近景特写 / 夜晚**（夜晚用于白闪探针）。

## 7. 验收（步骤 6 执行）

1. 七效果逐个截图取帧，按 §0 两条判据判定；
2. 夜晚跑亮度探针（复用既有 `readPixels` 逐帧亮度探针 + 触发抓帧，见设计文档 §9-3/§10）确认无新白闪；
3. 副本内 `vitest` 166 例全绿 + `tsc` 干净（新增效果断言应使其增加）；
4. 产出结论文档 + 截图目录，交委托方判定；相似度过低 → 回步骤 3。

## 8. 风险与回退

| 风险 | 应对 |
| --- | --- |
| 生产源码被污染 | 已隔离：生产 `web/` 零改动，全部工作在 `web-fxspike/` |
| 效果在真材质上做不出来 | 如实记录为结论（这正是验证的目的） |
| 湍流最贵（粒子池 + 限流 + 涟漪接线 + 细分提升） | 排最后做；先做片元侵蚀主力，粒子为可选增强 |
| 提取帧机制不成立 | 已提前实测 headless WebGL 可行；URL 参数驱动是对「simTime 推不动」的直接应对 |

**实施顺序**：底座（属性 + 接线 + 断言）→ **4.2 拉扯**（已知失败点，先验）→ 4.1 融合 → 4.5 潜流 → 4.4 暗流 → 4.6 凝结 → 4.7 死亡 → 4.3 湍流（最贵）。
