# 待立项清单 · 关系网缺失能力（另立项实现）

日期：2026-09-10 ｜ 用途：**另一条工作线**的输入文档。本清单只记录"缺什么、出处、现状证据、
坑在哪"，不含实现方案——方案由那条线自己设计。

配套：组件化（`<droplet-net>`）作为**并行**的一条线推进；本清单是它的下游消费方。
两条线共享的接入面见 §4。

## 0. 现状基线（本清单的证据来源）

- 前端封版状态：`web/` 工程 166 例测试绿、`tsc` 干净、build 四入口通过
  （2026-09-10 实跑；见 `docs/会话交接-2026-09-10.md`）。
- 已实现：模块①物理（`web/src/watersim/`）、模块②交互（`web/src/interaction/`，
  拖拽/悬停/聚焦编舞）、模块③光影渲染（`web/src/lighting/` + `grayview/luxShaders.ts`）。
- **全代码库不存在**「章节 / 张力 / 死亡 / 退场状态 / 未出场 / 灰色 / 人名标签」概念
  （检索证据：`grep -rn "章节|张力|死亡|退场|未出场|label|名字" web/src` 仅命中
  「焦点退场」这类交互词；`viewer.ts` 的关系网是写死的 7 滴六边形布点，
  `watersim/engine.ts` 只有几何意义上的液滴，无语义字段）。

## 1. 必须先裁决的前提（不裁决，两条线的设计会各写一版）

1. **2D 还是 3D**：产品规格 §7.1 写明「关系网始终是 2D 画布，PixiJS + WebGL 自定义
   shader + d3-force；Three.js 属未来升级路径」，但实际做出来的是 three.js 三维水体版
   （`luxview.html`，含真实水面场/液滴/液桥/聚焦编舞）。**缺失功能按哪一版继续，需先定**
   ——它决定技术选型、性能预算（规格 §7.1 要求「只渲染视口内元素、标签页隐藏暂停」）与
   规格是否要修订。
2. **「拉伸不断裂」是否翻案**：现物理有明确裁决「液桥拉伸不断裂」（第三批②修订，
   `watersim/bridges.ts` 生存期注释、`bridges.test.ts` 守护）。而规格 §7.3「疏远/低强度」
   要求拖拽超阈断裂 + **章节转场中关系结束为永久断裂**。两条规则需合并成一条。
3. **§3/§4 的「技术受限」具体卡在哪**：据委托方 2026-09-10 说明，动效文档 §三（关系状态
   纯流体表达）与 §四（人物个性化动效）因技术限制暂缓。这两项的形态直接决定清单
   A-5 转场能做到什么程度（见 §2-B 的依赖提示），建议先做**最小验证**再排期。

## 2. 缺失清单

### A. 纯「没做」（后端数据到位即可实现）

| # | 缺失能力 | 出处 | 现状证据 | 要点 / 坑 |
| --- | --- | --- | --- | --- |
| A-1 | **人名标签** | 动效 §1.1；规格 §7.2、§2.3 | 零文字渲染（全工程无 label/text sprite 相关代码） | 规格 §7.2 还要求：节点多时按密度缩小半径，低于下限则**隐藏名字**，悬停或聚焦时再显示；未出场角色**不给名字**（§2.3） |
| A-2 | **关系 → 液桥形制** | 动效 §1.2/§1.3；规格 §7.3 | 液桥形制统一，无数据来源（`watersim/bridges.ts` 只有几何/物理量） | 类型→表达映射（融合/拉扯/对撞/暗流/潜流）+ 强度→粗细与弹簧强度，钳在视觉安全区间；⚠ 受裁决前提 2 制约 |
| A-3 | **人物状态与灰滴** | 动效 §2.3 后半 | 聚焦模式（`engine.enterFocus`）只做「中心 + 直连邻居围圈」，无状态维度 | 死亡已退场 → 显示文字关系说明；未出场 → 显示「未知关系」且**水滴中间无名字**；灰色水滴**无动态关系表达**；进入聚焦后**数秒渐次从水底浮现**，并与中心形成**半透明水柱** |
| A-4 | **整体阅览** | 动效 §2.4 | 无 | 显示全部人物及其关系（含死亡/未出场），**去掉所有动态表达、仅文字说明**；规格 §8.4：overview 无章节切换、不触发转场 |
| A-5 | **章节滑块 + 转场系统** | 动效 §5 ↔ 规格 §8 | 无任何章节概念；唯一的时间线是 `demo.ts` 的演示脚本 | 张力公式与阈值 T=1.0（规格 §8.1，权重集中在一个常量文件，设计为可按书覆盖）；小变化五阶段（§8.2，≈1.2-1.8s）；大转折三阶段（§8.3，≈2.5-3.5s）；滑块 150ms 防抖 + **松手触发**；跳跃式切换 = 全区间 delta 一次转场；**转场期间输入冻结**；首载直接渲染当前章节状态、不触发转场 |
| A-6 | **人物卡浮层 + 编辑模式** | 规格 §6（focus/浏览/人物卡/编辑模式） | 无 | 右键浮层；编辑模式含改名/合并/拆分人物、关系增删改；`confidence<0.7` 标「待确认」；人工修正优先于 AI 结果（规格 §3 `user_edits`）。偏产品功能，可能归后端线 |

| # | 缺失能力 | 出处 | 要点 / 坑 |

### C. 数据依赖

A-1 ~ A-6 全部吃 `characters / relations / events`（**一切带章节锚点**，规格 §3 六张表）。
建议：功能线先用 fixture 推进，但字段直接对齐规格 §3 + §8.1 张力公式，省一轮返工；
`GET /graph` 一次返回全书带锚点数据、章节视图与 delta 由客户端本地计算（规格 §3 末）。

## 3. 与后端的关系

- 后端（AI 提取管线 + SQLite + 书库/阅读器，见 `docs/superpowers/specs/2026-09-02-…-design.md`
  §3/§4/§5/§9）是该线**数据侧的最终来源**；本清单的 A 组可以直接按规格 §3 的字段设计，
  不必等后端跑通。
- 张力/阈值等常量按规格 §8.1 设计成可被 DB 字段覆盖（v1 先集中在一个常量文件）。

## 4. 与组件化线的接入面（并行时必须对齐的部分）

组件线（`<droplet-net>`，见其设计文档）对外提供：

1. **数据契约**：人物 / 关系 / 章节 / 事件四类输入，**字段位按本清单 §2-C 与规格 §3 预留**
   （状态、章节维度从第一天就在契约里，实现由功能线补）。
2. **事件外抛**：点击/悬停液滴、进入/退出聚焦、章节变化等——A-6 人物卡浮层与 A-5 转场的宿主接线走这里。
3. **渲染挂载点**：功能线的视觉内容（标签、灰滴、转场编排）以独立模块接入，不重写宿主外壳。

约定：契约由组件线拥有并唯一；功能线只消费。契约变更需同时知会两条线并记录。
