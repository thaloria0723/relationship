## 需求与实现

| # | 需求(委托方原话要义) | 实现 |
|---|---|---|
| 1 | 聚焦模式下中心液滴须占据正中位置,包围圈(与中心直连的液滴)须在相机视角内(相机位置按具体情况调整);此时液桥长度强行变为一致 | ①相机:视点目标 = 中心滴悬浮位(屏幕正中,X 轴像素级);高度按等长环半径逐次拟合 `h = (L + maxR + focusFitMargin)/tan(min(半垂直FOV,半水平FOV))×1.12`,俯角 0.12h。②等长化:`enterFocus` 把全部 spoke(中心直连桥)restLen 强制 = L(= 最长 spoke 距与持距下限取大,只外推不内拉);`focusOrbitRadialK` 一阶收敛把成员水平半径拉到 L(实测六滴半径差 <1e-6 m,正多边形环) |
| 2 | 聚焦模式下中心滴下方水面不断产生圈状涟漪;包围圈液滴除与中心相连的液桥外其他液桥全部暂时断裂;包围圈液滴缓缓绕中心顺时针转动 | ①涟漪:`focusRipplePeriod=0.45s` 周期经弹坑发射器在中心滴位置注入 `focusRippleVolume=4e-6`(×(r/0.02)² 尺度归一)→ 扩散圆环串。②断桥:`enterFocus` 切断全部非 spoke 组相关桥(包围圈内部 + 跨界;网络场景实测 12 条);**暂时** = 收尾时恢复。③旋转:`applyFocusOrbit` 给成员写轨道速度 v = kr(L−r)·e_r + ω·e_θ,`focusOrbitOmega=0.4` rad/s;正值 = engine 平面逆时针 = 俯视屏幕顺时针(实测 3s 整体转过 67° = 0.39 rad/s,与悬浮段 exp(−4dt) 阻尼系数 0.975 精确一致) |
| 3 | 退出聚焦:中心液滴直接自由落体回第一次下落的固定点;其他液滴做曲线运动回各自第一次下落的固定点;暂时断裂的液桥恢复连接 | ①中心:`exitFocus` 水平归位出生锚点(anchor = 首次入水点)+ `setLevitate(false)` → 空中段自由落体,实测精确落在 (0.5, 0.5)。②成员:引擎编舞二次贝塞尔(水平,smoothstep 缓动;控制点 = 弦中点 + 顺轨道切向垂直偏移 → 顺势螺旋回位)+ u² 缓入下降(衔接落水),`focusReturnDur=1.0s`,落水经弹坑通道溅落;实测半程偏离弦中点 60.5mm(曲线显著)。③恢复:全员到位后 `finalizeFocusExit` 恢复 cut 桥与原 spoke 桥长(实测 18/18 恢复、0 切断);**恢复刻意延后到编舞收尾**——立即恢复会让跨组桥在成员尚在环上时把组外端拉离原位 |

## 关键裁决(委托方需求引申,新会话勿翻案)

- **编舞期守护(按构造满足「恢复连接」)**:聚焦期与退场编舞期,组相关桥
  `guardSlot=1`(不张力/不断桥/不复检侵入)、成桥扫描全局面冻、组内滴
  `intruderExempt=1`(悬浮/旋转/回场飞行的 2D 投影不作为无关桥的侵入第三方)。
  没有守护时:中心滴退出即转空中段(floating=0),spoke 会被端点失效规则立即
  永久断桥——「暂时断裂恢复」无从谈起。
- **断桥恢复时机 = 编舞收尾**(非退出瞬间):成员曲线归位与网络张力恢复同步,
  避免「 stretched 桥拽飞组外端」;语义序列与需求③一致(回位 → 恢复)。
- **液滴尺寸恒定/连接语义等既有裁决全部沿用**,本批未触碰 pairs/capillary/流动。

## 实测数据(浏览器端到端,网络场景 7 滴 18 桥)

- 取景:中心滴屏幕 X = 640 = 正中(Y 向 ±7px 为涟漪波面垂直起伏,平均居中);
  包围圈全部入画,最小边距 106px(1280×720);相机 h=0.51m 按 L=0.131 逐次拟合。
- 等长环:六成员半径 0.1253172 ± 1e-7 m(含不同大小滴:0.022 中心 + 0.016/0.013 环)。
- 断桥:12 条非 spoke 桥全部 cut;6 条 spoke 保留渲染;张紧持有 L。
- 旋转:3s 内六滴角度整体 +67°(0.39 rad/s);中心滴水平漂移 <26µm/1.5s。
- 涟漪:场 maxAbsH 1.7e-3 → 2.0e-3 持续受激;单圈峰深 ~2.5mm。
- 退出:Esc 后 200ms 中心已坠落近水面 (0.5,0.5) 锁定;成员曲线半程偏离弦中点
  60.5mm;收尾后 18 桥全恢复(0 cut)、全员锚点误差 ≤0.1mm、相机回原视角。

## 教训与备忘

- e2e 双击派发:pointerdown/up **必须分帧**(控制器 `downEdge` 只在
  `pointer.down=true` 时登记双击基准,同帧派发双击永不成立);且双击的
  第一次按下会按既有设计触发一次微拖拽(ray∩水面目标点与滴心存在高差偏移),
  自动化判读时须区分测试噪声与产品行为。
- 增删 `src/**/*.test.ts` 文件会触发 Vite 整页 reload(依赖图变化),走查中途
  状态会清零;先删探针测试再开浏览器走查。
- 涟漪对照测试基线不安静:入水瞬态 ~6e-3、成桥推挤与 homeK 晃动都会注波,
  隔离机制须「无桥单滴场景 + 等长预沉降 + 窗口采样」。

## 遗留观察项(非缺陷)

1. 中心滴悬浮期垂直随波起伏(±2mm → 屏幕 ±7px),若委托方要求绝对静止,
   可在 hold 期把 lev 的 zTarget 冻结为进入时刻值(观感取舍,待反馈)。
2. 双击首按的微拖拽偏移(几 mm,释放后回弹锚点)为点击/拖拽共用的既有行为,
   本批未动;若观感介意可在控制器加「点击静止判定」。
3. `交互系统设计-2026-09-07.md` §4 特性④的描述已被本批扩展(等长环/旋转/涟漪/
   退场编舞/恢复时机),须计划会话同步修订。
