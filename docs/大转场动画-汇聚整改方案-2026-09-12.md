## 0. 需求原文(判定基准,勿改写)

**委托方 2026-09-12 整改点(原文):**

> 「液滴向中心汇聚这里,改成**液滴全部溃散成和大液滴爆发时溅射出来的光点一样**,然后
> **光点像漩涡一样向中心汇聚**,最终**凝聚成大液滴(大液滴是光点凝聚而成,从无到有)**,
> 随后**大液滴凝滞一瞬,然后炸裂**,**之后的动画和现在保持一致,不做改变**。」

拆成四条可判定项:

| # | 要求 | 落点 |

| R2 | 光点**像漩涡一样**向中心汇聚 | 极坐标收缩 + 角速度递增(差分自转),按源位置分旋臂 |
| R3 | 光点**凝聚成大液滴**(光点凝成,从无到有) | 巨滴以 hashed discard **反向物质化**(尺度不做生长 —— 灰滴「从无到有」同一纪律),与光点抵达窗重叠 |
| R4 | 大液滴**凝滞一瞬**,然后炸裂;**其后动画不变** | 凝滞后爆散/牵引/定格参数与曲线一字不动 |

## 1. 现状与差距(步骤 1-2 盘点结论)

现有汇聚段(`fxdriver.ts` `convergeState` + `TRANSITION`):

- 旧滴**螺旋滑入**中心(`pos = C + rot(θ0+1.6p)·r0(1−easeInCubic(p))`),**缩尺 1→0** 被核心滴长成的巨滴吞并;
- 旧桥卷曲(`turb`) + 卷入收缩(`grow 1→0`);
- 核心滴汇聚段保持原大,过渡段**长成** 4.2× 巨滴。

与 R1-R3 的差距:① 滴是「滑进去」不是「溃散成光点」;② 巨滴是**长大**的,不是光点凝成的
「从无到有」;③ 全程没有光点。R4 已满足(爆散之后不动即可)。

**可复用的既有通道**(本轮不新增 shader、不新增 uniforms、不引 post pass):

| 通道 | 出处 | 本轮用途 |
| --- | --- | --- |
| `dissolve`(hashed alpha discard;丢弃不写色不写深度) | 死亡收尾 / 灰滴与新章滴「从无到有」 | 旧滴**溃散**消失;巨滴**反向**物质化 |
| 火花池(`sparkMesh`,透镜几何 + `LUX_SPARK_*` 珠光,逐实例矩阵) | 爆散段 48 颗 | **同一池**改作汇聚段的「光点」;容量 48→96 |
| `flash`(HDR 闪点,shader 内钳制) | 凝结 / 爆散 | 溃散「噼」的一下 + 凝聚成滴的亮起 |
| `fogCue` / `transitionMix`(压暗+增辉) | 过渡段 | 不变(凝滞段的雾裹与水下模糊) |

关键约束(交接 §3 铁律,继续有效):液滴不透明写深度 → **禁 alpha 淡出**(只走 dissolve/
scale/lift);uniforms 五个材质共享;`three` 只许 viewer.ts import;效果驱动 three-free 可单测。
**新约束(本轮实测得出)**:水底软影/焦散吃**引擎半径**(`dropRadArr[n]=state.r[i]`),
渲染侧 dissolve 藏不掉它 → **旧滴溃散完成必须及时从引擎删除**(死亡退场同一教训)。

## 2. 步骤 3:互联网调研与引用

### 2.1 物体溃散成粒子(disintegration)

- **Codrops《Implementing a Dissolve Effect with Shaders and Particles in Three.js》**(2025-02-17)
  —— 标准做法 = 噪声阈值 dissolve(`discard`),**粒子只从溶解前沿(edge band)发射**,
  粒子带 `velocity` 属性逐帧推进,bloom 只加在溶解边缘。
  <https://tympanus.net/codrops/2025/02/17/implementing-a-dissolve-effect-with-shaders-and-particles-in-three-js/>
  (参考实现:JatinChopra/emissive-dissolve-effect <https://github.com/JatinChopra/emissive-dissolve-effect>)
  → **取用**:「溃散 = dissolve + 光点由 CPU 池发射」这一分工;不取「粒子挂在网格 shader 里」
  —— 本工程粒子是独立 InstancedMesh(与雾团/火花同构),且量级小、无 GPGPU 必要。
- **Codrops WebGPU/TSL《Gommage: Dissolving MSDF Text into Dust and Petals》**(2026-01-28)
  —— WebGPU 下 `Points` 不支持可变点径,改 **InstancedMesh + 属性打包**(birth/life/seed/scale
  压进一个 vec4),粒子走生命周期缩放/淡出 + Perlin 湍流。
  <https://tympanus.net/codrops/2026/01/28/webgpu-gommage-effect-dissolving-msdf-text-into-dust-and-petals-with-three-js-tsl/>
  → **取用**:与本工程「逐实例矩阵 + 逐实例属性」同构,验证了路线;属性打包暂不需要(量级小)。

### 2.2 粒子漩涡向心汇聚(vortex inward)

- **漩涡的物理关键是差分自转**:角速度随半径减小而增大 —— MiniMax `shader-dev`
  particle-system 参考的 Vortex/Storm 段给出 `angularSpeed = k / (offset + radius)`
  (另有 `smoothstep(innerR, outerR, dist)` 的中心暗核)。
  <https://github.com/MiniMax-AI/skills/blob/main/skills/shader-dev/reference/particle-system.md>
  → **取用**:本方案把「角度随进程加速」写成 `θ = θ0 + TWIST·p^1.7`、半径 `r = r0·(1−easeInCubic(p))`
  —— 先在外圈慢慢转、越靠近中心转得越快、最后被吸入,即 `ω ∝ 1/r` 的离散等价。
- **极坐标收缩式漩涡**(three.js forum「水/管道漩涡」thread):`angle = atan2(dy,dx) + t·k`,
  `r` 随时间收缩 → 内旋螺线;按源方位把粒子分到几条**旋臂**上(对数螺线 `r = a·e^(bθ)`,
  风车星系 Three.js 实现)才不会读成同心圆环。
  <https://discourse.threejs.org/t/how-to-create-water-falling-out-of-pipe-effect-using-shaders/81529>
  <https://blog.csdn.net/qq_38261626/article/details/157686235>
  → **取用**:每个光点以**其源滴的方位**为旋臂基准(`φ_s ± 散开`),个体再加角度/半径/时长抖动
  —— 与火花段「48 颗同步同距 = 规整圆环」的整改教训同一条。
- **黑洞吸积参考**:wagiham/threejs-cosmic-modes 的 Black Hole 模式(same repo,GLSL)
  ——「matter spirals rapidly inward toward a luminous core」。
  <https://github.com/wagiham/threejs-cosmic-modes>
  → **取用**:「快速内旋 + 中心亮核」的读感目标;中心亮核 = 本轮凝聚出的巨滴。
- 前情(上轮已引,继续有效):粒子 morph 的通用形态 `pos = lerp(A,B,ease(t)) + swirl(t)`
  (Kshitij978/Three.js-Point-cloud-morphing-effect、mmdalipour/particle-morph)
  —— 本轮把它换成极坐标形式(上式的直线插值在「漩涡」读感上不够)。

### 2.3 粒子凝聚成体(assemble / 从无到有)

- 社区主流 = GPGPU/FBO 位置纹理 + 向目标点的吸引(threejs-particle-shader 的
  `targetPosition`/`targetTexture`/`velocityFunctionString` 三件套)
  <https://www.jsdelivr.com/package/npm/threejs-particle-shader>
  → **不采用**:本工程量级 ≤96 颗,CPU 逐实例矩阵远够(GPGPU 是上一轮已裁决排除的路线);
  且本工程纪律「物理 CPU 单真源 + 效果纯逻辑可单测」要求 fxdriver 可单测。
- 「从无到有」在本工程已有**验收过的等价物**:hashed discard 反向物质化(灰滴浮现
  2026-09-12 委托方退回「小滴扩大」后整改通过;新章滴物质化同款)。
  → **取用**:巨滴 `dissolve 1→0` 物质化,**尺度恒 4.2×**(不做任何生长)。

### 2.4 节奏(沿用上轮 motionsites 质量口径)

anticipation(旧桥起卷缠绕,蓄力)→ impact(溃散 + 漩涡加速吸入)→ settle(凝聚成滴 + 凝滞悬停)
→ 爆散。辉光克制(夜闪纪律:加性项与时间调制项都要钳)。

## 3. 方案设计

### 3.1 时间线(总长 3.30s 不变;爆散点 1.75 不变 —— R4)

```
0     0.16        0.52     0.78        1.30        1.75    2.05      2.85    3.30
│ 预兆 │  溃散(7 滴错峰溶解成光点)  │  漩涡汇聚(光点螺旋向心加速)  │ 凝聚 │  凝滞悬停  │ 爆散 │  牵引  │ 定格 │
 旧桥起卷→0.40 全部卷没          光点 0.98–1.18 错峰抵达      巨滴从无到有  微呼吸+雾+压暗   ── 以下完全不变 ──
```

| 段 | 窗口(s) | 内容 |
| --- | --- | --- |
| 预兆 | 0 → 0.40 | 旧桥卷曲(`turb` 起)并卷入收缩(`grow 1→0`);**必须早于第一次引擎删除**(0.42) |
| 溃散 | 0.16 → 0.63 | 7 滴按索引错峰 `dissolve 0→1`(每滴 0.20s;环滴 0.16/0.205/…/0.385,核心滴最后 0.43,压轴) |
| 漩涡 | 0.21 → 1.22 | 光点从各源滴位置起飞,极坐标内旋(见 §3.2);错峰抵达 0.92–1.22 |
| 凝聚 | 0.63 → 1.30 | 核心滴(引擎里一直在,渲染上已隐形)`dissolve 1→0` 物质化,**scale 恒 4.2**(从无到有) |
| 凝滞 | 1.30 → 1.75 | 巨滴微呼吸(`1+0.028·sin(8.5t)`)+ 微升(`lift=0.02·mp`)+ 蓄力辉光(0.1)+ 雾裹 + 压暗 —— **与现行一致** |
| 爆散起 | 1.75 → | **一字不动**(flash 峰值 + 缩零 + 火花池 48 颗,参数与曲线沿用) |

引擎侧删除时序(`main.ts transitionSettle`):环滴在「溃散结束 + 0.06 余量」时**逐个**从引擎删除
(0.42 → 0.645,**从最高索引往低删** —— 交换删除不搬动低索引,索引即源序号);
核心滴照旧留到爆散末删除。删除 = 水底软影/焦散随之消失(§1 新约束)。

### 3.2 光点状态(纯函数,可单测)

每颗光点 `i` 在 `setTransitionSources` 时预计算(全部来自 `hash01`,无状态、可复现):

```
源 s:中心 P_s、半径 R_s、方位 φ_s = atan2(P_s.y−0.5, P_s.x−0.5)
t0_i = shatterStart(s) + 0.05 + 0.06·h1          // 随其源滴溶解而出现
t1_i = 1.18 − 0.20·h2                            // 错峰抵达(0.98–1.18)
θ0_i = φ_s + (h3−0.5)·0.5                        // 旋臂基准 ± 散开(按源分臂,不成同心环)
r0_i = |P_s−C| + R_s·(h4−0.5)·1.4                // 源滴盘面内的散布
h_i  = 0.012·h5                                  // 贴水微弧的个体高度
rad0_i = 0.009 + 0.004·h6                        // 光点半径(与爆散火花同量级)

运行期(p = span01(t, t0_i, t1_i)):
r  = r0_i · (1 − easeInCubic(p))                 // 半径先慢后快 → 吸入感
θ  = θ0_i + TWIST · p^1.7   (TWIST = 3.4 rad)    // 角速度递增 → 漩涡(差分自转)
x  = 0.5 + cos θ · r ,  y = 0.5 + sin θ · r
h  = h_i · sin(π p)                              // 光点不是子弹:贴水微弧
rad = rad0_i · (1 − 0.45 p)                      // 越接近中心越小(凝聚)
a  = min( span01(t, t0_i, t0_i+0.07), 1 − span01(p, 0.72, 1) )   // 出现快、抵达前融入
```

个体散布(实测调参：**静帧里要能读出螺旋而不是「一圈珠子」**，靠两件事):
`dθ = (h−0.5)·0.7`(旋臂有宽度)、`dr = (h−0.5)·1.8·R_s`(起点铺在滴盘面内外),
抵达窗取宽(`0.92–1.22`)→ 同一时刻各点半径分层、旋臂在人眼里连成螺线。

- **同款光点**(R1):走同一 `sparkMesh` / `LUX_SPARK_VERT|FRAG` 珠光材质、同一 `spark(i)`
  入口 —— 视觉与爆散火花**逐像素同款**,只是一个向内一个向外。
- **池容量 48 → 96**(`viewer.ts` `SPARK_MAX`;`POOL=96` 常量在 fxdriver)。按源半径比例分配
  (`n_s ∝ R_s`,下限 4,余数给最大源):核心 21 + 大环 14×3 + 小环 11×3 = 96。
  爆散段仍只用前 48 槽(`SPARK_COUNT` 不变) → **爆散视觉零变化**。
- 光点不带 `ox/oy`(滴不动)——汇聚段不再需要逐滴渲染偏移,该通道连同 `convergeState`
  一并**删除**(死代码清理;液桥端点回到直读滴位,`syncDroplets→syncBridges` 的先后顺序仍因
  中面锚缓存而必须保留)。

### 3.5 测试点(步骤 5;focused、纯逻辑)

1. **溃散**:每颗旧滴在其窗口内 `dissolve` 单调 0→1,`scale ≡ 1`(不缩不涨),`ox/oy` 不存在;
   核心滴的溃散窗**晚于**全部环滴(压轴),且各滴窗口互不重叠超过错峰半程。
2. **删除时序**:`transShatterEnd(i)` 随 `i` 递减(降序删除安全);全部环滴 < 爆散点;
   核心滴不参与早期删除。
3. **光点-出现**:`t < 源滴溃散窗` → `spark(i)=null`;之后 `a` 从 0 升到 1(≤0.07s)。
4. **光点-漩涡**:半径单调减、角度单调增、角速度在末段更大(p^1.7);`r→0` 时位置收敛到域中心。
5. **光点-吸收**:`p ∈ [0.72,1]` 时 `a` 单调降至 0,抵达后 `spark(i)=null`(与巨滴物质化交接)。
6. **光点-池**:分配总数 = POOL、每源 ≥4、核心源分到最多;`spark(i)` 对 `i ≥ 分配数` 恒 null;
   同参重复调用逐位一致(确定性)。
7. **凝聚**:巨滴 `scale ≡ 4.2` 全程(不许出现生长);`dissolve` 单调 1→0;凝聚窗与光点抵达窗重叠。
8. **R4 守护**:爆散/牵引/定格全部既有断言**原样保留**(同参数下数值逐位不变);
   另加一条:`spark(i ≥ SPARK_COUNT)` 在爆散段恒 null(池扩容不得把火花从 48 变 96
   —— 此回归由步骤 6 证据帧抓到,见结论文档「迭代记录」)。
9. **回归**:`fx=0` 基线、非 mode 9 路径不受影响(既有套件)。

### 3.6 判据(步骤 6)

1. **R1-R4 逐条**:证据帧中可辨「溶解成点 → 旋臂漩涡 → 凝聚成滴(无生长)→ 凝滞 → 爆散」;
2. **对照爆散光点同款**:汇聚帧的光点与 `t2.15` 火花帧的光点形态一致(同材质同尺寸族);
3. **motionsites 节奏**:蓄力(卷曲)→ 冲击(溃散/吸入)→ settle(凝聚/凝滞)四拍清晰,无匀速感;
   辉光克制不泛白;
4. **回归**:vitest 全绿 + `tsc` 干净 + `fx=0` 基线帧不变。
   相似度过低 → **回步骤 3**。

## 4. 风险与边界

1. **核心滴隐形窗口(0.63–0.78)的软影残留**:已压到 ≈0.15s 且处于「漩涡眼」最忙时刻;
   若步骤 6 证据帧仍可辨 → 备选:提前凝聚窗起点(光点抵达前巨滴先半透出)。
   **不**采用「删核心滴再重新 spawn」:spawn 从水面之上 0.15m 落下,与「凝聚而成」相悖。
2. **光点不带物理**:漩涡是渲染侧编排,水面不被搅动(与上轮「编排与物理解耦」同一边界)。
3. **96 颗 × 每帧逐实例矩阵**:CPU 侧 ≤96 次矩阵写,量级同爆散段,无性能风险;
   `sparkAt` 未注入时 `count=0` 零开销纪律不变。
4. **凝聚的『从无到有』是屏幕空间抖动渐显**,不是几何生长 —— 与灰滴物质化同款(已验收);
   若委托方要「光点拼出液滴」的更强读感,需新通道(粒子吸附成壳),另议。
5. 总长、爆散点、牵引/定格参数**不动** → 滑块冻结(3.3s)、`transitionSettle` 阈值幂等结构不变。
