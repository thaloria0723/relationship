# 水滴关系网小说阅读器 · 设计规格

日期：2026-09-02
状态：已确认设计（待用户审阅）

## 1. 概述

辅助阅读长篇小说的本地 Web 应用：导入小说后，AI 逐章提取人物、关系、事件，生成**带章节锚点的人物图谱**；核心界面是「水滴关系网」——以水滴（人物）与液桥（关系）组成的动态关系网，支持拖拽变形、悬停放大、聚焦模式、整体阅览，以及由「叙事张力」驱动的章节转场动画。

**灵感与痛点**：《百年孤独》式的人物关系复杂多变、《哈利·波特》式的情节曲折，阅读时容易忘记谁是谁。

### 1.1 v1 交付范围

- 书库页（导入 .txt / 粘贴文本 / .epub，书籍管理）
- 水滴关系网视图：浏览 / 聚焦 / 整体阅览三模式 + 章节滑块 + 转场动画 + 浮动人物卡（右键）
- 阅读器：左侧可收起章节目录 + 中间正文（无右栏）
- AI 提取管线：分章增量提取 + 合并消歧 + 断点续跑 + 结果缓存
- 人工基本修正：编辑模式（改名 / 合并 / 拆分人物；关系增删改），防重提取覆盖
- 数据存储：SQLite 单文件，一切状态可恢复

### 1.2 非目标（后续版本）

- **时间线栏目**（与关系网同级的独立栏目，下期项目；但事件数据本期仍提取——死亡事件是张力系统与死亡动效的输入）
- **人物卡完整界面**（本期只有右键浮层；浮层点击跳转留接口）
- 段落级实体标注（正文内联高亮）
- 3D 视图（数据模型与视图解耦，为未来 Three.js 留路）
- 超长网文（>1000 章）的分批合并
- 多用户 / 认证 / 在线同步
- 真流体仿真（SPH 粒子级）
- 图片 / OCR 导入

### 1.3 成功标准

- 30 万字小说全流程提取成本约 $1-3
- ≤200 节点的关系网在持续动效下保持 60fps
- 章节转场动画符合《水滴关系网核心动效设计文档》的描述
- 用户可人工修正 AI 提取错误，修正不被重提取覆盖
- 进程重启后从断点恢复，不重复付费

## 2. 架构总览

单仓库两个包 + 共享类型，一门语言（TypeScript）、一个进程、一条命令启动：

```
repository/
├── server/          # Node + Express + better-sqlite3 + @anthropic-ai/sdk
├── web/             # React + TypeScript + Vite + PixiJS(WebGL) + d3-force
├── shared/          # 前后端共用类型（人物/关系/事件/API 契约）
└── docs/
```

- 开发时 Vite 代理 `/api` 到后端；生产时后端直接托管 `web/dist`
- AI 调用只发生在服务端（API key 不进浏览器）
- 提取结果按章持久化（SQLite），重开应用不重复付费

**端到端数据流**（导入一本小说）：

1. 用户上传 .txt/.epub 或粘贴文本 → 服务端探测编码 → 分章 → 章节入 SQLite（状态 `待提取`）
2. 内存队列逐章提取（并发 2-3）：Haiku 4.5 读本章文本 → 结构化 JSON（人物/关系/事件）→ 按章落库
3. 全部章节完成 → 合并阶段：Opus 5 对全书结果做人物消歧、关系生命周期、事件归位 → 物化最终图谱
4. 前端收到完成通知 → 关系网按滑块章节渲染；进度经 2 秒轮询刷新

## 3. 数据模型（SQLite，六张表）

核心原则：**一切带章节锚点**——这是「图谱随章节演进」的载体。

### novels
```
id, title, author?, source_format(txt/epub/paste), created_at,
chapter_count, extraction_status(待提取/提取中/合并中/完成/失败), total_tokens_spent
```

### chapters
```
id, novel_id, number, title?, raw_text, char_count,
extract_status(待提取/提取中/完成/失败), extract_json, retry_count
```

### characters
```
id, novel_id, name, aliases(JSON), first_seen_chapter, last_seen_chapter,
importance(0-1，合并阶段由出场次数/叙事比重计算), summary(一句话简介), color
```

### relations
```
id, novel_id, char_a_id, char_b_id,
type(亲属/朋友/恋人/敌对/师生/利用/秘密/疏远/其他),
direction(none/a_to_b/b_to_a，仅「利用」必须带方向),
hidden(bool，仅「秘密」为真),
strength(0-1), confidence(0-1),
first_seen_chapter, last_seen_chapter, source_chapter,
description, quote(原文引文，证据锚定)
```

- 同一对人可有**多条不同 type 的记录**，靠章节区间区分（先「兄弟」后「仇人」= 两条记录）——这是关系演进的载体，也是转场 delta 中「类型变化」的来源
- `confidence < 0.7` 的关系 UI 标「待确认」

### events
```
id, novel_id, chapter_id,
type(人物登场/人物死亡/关系确立/关系破裂/重大情节),
description, characters(JSON，相关人物 id), quote(原文摘录；时间线栏目（下期）使用)
```

### user_edits
```
id, novel_id, target_type(character/relation/event), target_id,
operation(merge/rename/split/edit/delete/add), payload(JSON), created_at
```
人工修正在重新提取/合并时**优先于 AI 结果**，不被覆盖。

**演进查询**：章节 N 的图谱 = `characters WHERE first_seen ≤ N` + `relations WHERE first_seen ≤ N`。全书量级 ≤200 节点，`GET /graph` 一次返回全量带锚点数据，任意章节视图与 delta 由客户端本地计算，无需实时聚合。

## 4. AI 提取管线

### 4.1 导入与分章

- 编码自动探测（GBK/UTF-8 等，中文小说常见坑）
- .txt：按中文章节正则（`第[一二三四五六七八九十百千零〇两0-9]+[章回节卷]`）分章，无匹配时按空行回退
- .epub：用成熟解析库解包，取目录节点为章节
- 单章 >3 万字的罕见长章内部切块，结果并入本章
- 粘贴文本：与 .txt 同一分章逻辑

### 4.2 分章提取（Haiku 4.5，一章一次调用）

结构化输出（`output_config.format` + JSON schema + `client.messages.parse()` 校验），每章产出：

```json
{
  "characters": [{ "name": "全名", "aliases": ["绰号/别称"], "role": "身份" }],
  "relations": [{ "char_a": "…", "char_b": "…", "type": "…",
                  "description": "…", "quote": "原文引文", "confidence": 0.9 }],
  "events": [{ "type": "人物登场|人物死亡|关系确立|关系破裂|重大情节",
               "description": "…", "quote": "原文引文", "characters": ["…"] }]
}
```

中文提示词约束：首次出现用全名；绰号进 aliases；**每条关系必须带原文引文**（证据锚定，抑制幻觉）；只提取本章确证的信息。

### 4.3 合并消歧（Opus 5）

所有章节的提取 JSON 汇总后一次调用（整本名著 ≈100-150 章，提取结果 ≈10-15 万 token，1M 上下文内）：
- **同名合并**：别名、绰号归并到主人物（老布恩迪亚 → 何塞·阿尔卡蒂奥·布恩迪亚）
- **同名消歧**：七代重名人物按语境区分为**不同人物**（《百年孤独》式难点，合并阶段的核心价值）
- 计算 `first/last_seen_chapter`、`importance`、一句话简介
- 关系补 `type`、`source_chapter`、`strength`、`direction`、`hidden`；章节间类型矛盾 → 输出带章节锚点的多条生命周期记录（判断「何时变」，不是「是什么」）
- 事件按章归位；死亡事件驱动「人物死亡」动效与张力权重
- 超长网文（>1000 章）：分批合并 + 实体表接力（留待后续，v1 单次合并）

### 4.4 队列与可靠性

- 内存队列 + SQLite 状态机；并发 2-3（温和限速）
- 429/5xx 指数退避重试 ×3；非重试类错误标 `失败` 并记录原因
- 单章失败不阻塞其他章；合并阶段带缺失章节照常进行（UI 标注）
- 进程重启从断点续跑；进度 2 秒轮询（单用户本地应用，轮询比 SSE 简单可靠）
- `extract_json` 持久化：重跑直接复用，不重复付费

### 4.5 成本预估

30 万字名著全流程 ≈ **$1-3**（分章 Haiku 4.5 $0.5-1.5，合并 Opus 5 $0.5-2）。

```

GET    /api/novels/:id                     详情（含提取状态、token 消耗）
GET    /api/novels/:id/chapters            章节目录
GET    /api/novels/:id/chapters/:num       章节正文
GET    /api/novels/:id/graph               全量图数据（带章节锚点，客户端本地算视图与 delta）
GET    /api/novels/:id/extraction/progress 提取进度（轮询）
POST   /api/novels/:id/extraction/retry    重试失败章节 / 重跑合并

```

## 6. 前端：关系网视图状态机

```
browse(N) ◄──图标切换──► overview
    │ 点击水滴              │ 点击水滴
    ▼ 点击空白返回           ▼ 点击空白返回
focus(C, N)             focus(C, 全书)
```

### browse（浏览模式，主画布）

- 章节 N 的图谱；**全书布局 + 本章变化高亮**（变化集 = 第 N 章新增人物/关系/类型变化/死亡）
- **拖拽**：被拖水滴固定到指针，相连液桥拉丝变细、邻居受牵引微移；松手释放，d3-force 弹性自然收敛
- **悬停**：鼠标区域水波折射放大 + 高亮；悬停水滴边缘泛涟漪；隐藏关系被「搅动」浮现
- **章节滑块**：拖动（150ms 防抖）→ 松手触发一次转场（4d 节）；跳跃式切换 = 一次叠加动画，不是逐章连播
- 点击水滴 → focus；点整体阅览图标 → overview

### focus（聚焦模式）

- 被点水滴平滑移至正中央，与其相连的水滴（邻域取**全书图**）向心聚拢成完美圆圈，缓缓旋转
- **灰色水滴**：与中心水滴相连、但当前章已退场（有死亡事件且 ≤N）或未出场（first_seen > N）的角色——进入聚焦数秒后从画面底部渐次从水底浮现，与中心水滴形成半透明水柱（静态、无动态关系表达）；已死者水柱显示关系文字，未出场者显示「未知关系」且水滴无名字（防剧透）
- **限制**：本模式无章节切换、无图谱编辑，纯查看
- 点击空白 → 所有水滴像溅落水面般向四周散开，回到 browse
- 从 overview 进入：全书邻域，无灰色过滤

### overview（整体阅览）

- **交互与浏览模式完全相同**（拖拽/悬停/点击聚焦/物理模拟持续运行），仅两点区别：① 显示全书全部人物与关系（含已死、未出场）；② 去掉关系线的动态表达（无气泡/湍流/单向冲刷），关系以**文字说明**呈现
- 章节滑块仅存在于 browse，overview 无章节概念

### 人物卡（浮层）

- 三模式统一：**右键水滴**弹半透明浮层人物卡（名字/别名/一句话简介/重要度），不阻断画布交互
- 鼠标移到浮层上单击 → 跳转人物卡界面（**该界面 v1 不做**，留接口）
- 聚焦模式中心水滴不放信息按钮

### 编辑模式

- 工具栏开关；开启后：右键水滴弹编辑菜单（改名/合并到另一人物/拆分/删除）；点击液桥弹关系编辑浮层（类型/强度/方向/隐藏/删除）；从水滴 A 拖到水滴 B 新建关系
- 所有操作写入 `user_edits`，重提取时优先于 AI 结果

## 7. 关系网渲染与动效

### 7.1 渲染与物理

- **渲染**：PixiJS + WebGL 自定义 shader——折射（背景透过水滴扭曲）、水面涟漪（顶点位移/UV 扭曲）、焦散（大转折水下模糊）、雾气聚散
- **物理**：d3-force——link 力（拉丝弹回）、charge 力（排斥）、collision 力（最小安全距离）、x/y 力（聚焦成圈/漩涡汇聚的目标牵引）；编排式演出 = 补间目标位置 + 力导向收敛
- 未来 3D 升级路径：Three.js + d3-force-3d（shader 技法平移，渲染层接口化）
- 液桥：Catmull-Rom 样条、两头粗中间细、微弱重力下垂 + 高频流体颤动
- 纯计算部分（曲线、波纹位移、张力、delta、类型→表达映射）全部做成**可单测纯函数**，shader 只负责呈现
- 性能：rAF + delta-time；效果粒子池 + 上限（融合气泡 ≤8/桥）；只渲染视口内元素；标签页隐藏时暂停

### 7.2 安全限度机制

- **距离下限**：无论关系多亲密，水滴不重叠；极致的亲密感由液桥「双向高光加速流动」和「水花融合感」表达
- **粗细限度**：液桥粗细严格限制在视觉安全区间，只与关系类型和强度挂钩；情感张力交由流速、水花颤动、排斥/吸引等动态细节承载

### 7.3 关系动态表达（流体语言）

| 关系类型 | 流体表达 | 视觉实现 |
|---------|---------|---------|
| 恋人 / 高强度亲属 | 融合 | 水滴极度靠近（不破安全距离），液桥粗壮近似无边界；高光 + 微气泡双向缓流 |
| 疏远 / 低强度 | 极限拉扯 | 液桥细长、光泽黯淡；拖拽超过断裂阈值 → 糖浆拉丝「啪」地断裂、断口收缩回水滴（拖拽为临时态，松手重生；章节转场中关系结束为永久断裂） |
| 敌对 | 湍流 | 液桥粗壮（限上限内）边缘水花飞溅/沸腾；两水滴高频颤动且电荷斥力增强 |
| 利用 | 暗流 | 密集微气泡/光点沿 direction 单向快速冲刷，无回流 |
| 秘密 | 水下潜流 | 平时半透明融入背景；鼠标高亮区靠近时才渐显流动纹理 |

强度 → 粗细/弹簧强度映射，钳制在视觉安全区间内。

### 7.4 人物个性化动效（转场中触发）

- **新人物凝结**：靠近相关人物处泛起水汽 → 雾气聚拢 → 瞬间凝结成水滴 → 向周围水滴抽丝拉出液桥、接入弹簧系统轻微晃动后平静
- **人物死亡**：边缘沸腾模糊 → 化作水蒸气向上飘散 → 相连液桥逐一断裂 → 原位残留短暂雾气

## 8. 章节转场与「叙事张力」系统

### 8.1 变化集与张力公式

滑块从 N 到 M（跳跃 = 区间叠加），delta = (N, M] 内的：新人登场、人物死亡、新关系确立、关系结束、关系类型变化（生命周期记录对比）。

```
张力 = Σ 各变化权重
  新人登场   = importance × 0.5
  人物死亡   = importance × 1.5        （最重的事件）
  新关系     = strength × 双方平均 importance × 0.6
  关系结束   = strength × 双方平均 importance × 0.8
  类型变化   = 双方平均 importance × 1.0；敌友反转类（敌对↔亲密）按 1.5 取上限
阈值 T = 1.0
张力 < T → 【小变化】；张力 ≥ T → 【大转折】
```

权重与阈值集中在一个常量文件（v1），设计为可改为**按书设置**（DB 字段覆盖默认值，后期加设置面板），不需要动引擎。

### 8.2 小变化动画（≈1.2-1.8 秒，五阶段）

1. **重击**：画面中心（或关键人物处）受击
2. **扩散**：一圈或多圈水面涟漪向外扫（shader 顶点位移/UV 扭曲）
3. **形变**：涟漪扫过处水滴液桥剧烈晃动拉伸、不断裂；**此处触发人物个性化动效**（凝结登场/死亡蒸发）
4. **重组**：波纹平息中，水滴顺势滑入新位置，新液桥如水流汇合生成
5. **静止**：新网络稳定

### 8.3 大转折动画（≈2.5-3.5 秒）

1. **汇聚**：水滴失去浮力，如荷叶水珠滚向屏幕中心漩涡，连线卷曲缠绕融为一体
2. **过渡**：巨滴水珠悬停 + 瞬间水下焦散式模糊
3. **迸发**：大水滴炸裂飞溅，无数小水珠向外飞射、空中减速悬停（时空静止感），随后被无形线牵引、拉长、连接，定格为新章节关系网

### 8.4 交互规则

- 滑块 150ms 防抖 + **松手触发**（快速拖动不逐章连播）；跳跃式切换 = 全区间 delta 一次转场
- **转场期间输入冻结**（1-3 秒禁用拖拽/点击），结束恢复
- 初次加载直接渲染当前章节状态（不触发转场）
- overview 无章节切换，不触发转场

## 9. 书库页与阅读器

### 书库页

书卡网格（书名/作者/章节数/提取状态徽章/提取进度条）；导入入口三合一（.txt 上传 / .epub 上传 / 粘贴文本弹窗）；删除书籍；点书卡进入工作区。

### 阅读器

左栏可收起章节目录 + 中间章节正文。与关系网共享 `{novelId, 当前章节 N}` 全局状态：切目录或滑块，双方同步。

## 10. 错误处理

- **导入**：编码探测失败 / 空文本 / 损坏 epub → 400 + 明确中文错误信息
- **提取**：429/5xx 指数退避重试 ×3；单章失败只标 `失败` 不阻塞全书，UI 显示重试按钮；合并失败 → 阶段标失败可重跑；合并时个别章节缺失 → 带警告继续
- **LLM 输出**：`messages.parse()` schema 校验，非法 JSON 重试一次后标失败
- **崩溃安全**：一切状态在 SQLite，重启从断点续跑
- **前端**：网络错误 → 提示 + 重试；轮询在错误时停止
- 客户端与服务端均通过 `shared/` 类型保证契约一致

## 11. 测试策略

- **服务端单测**：分章（中文章节正则 + 中文数字）、编码探测、epub 解析、SQLite 数据层
- **管线集成测试**：mock Anthropic client（测试不花真钱），覆盖导入 → 提取 → 合并 → 落库全流程
- **前端纯函数单测**（最易出 bug 的逻辑集中在纯函数）：Catmull-Rom 曲线、波纹位移函数、张力公式、章节 delta 计算、关系类型→流体表达映射、变化集计算
- **视觉验证**：内置固定样章（fixture 小说）+ 人工检查清单（shader 效果不设像素级对比）
- **E2E**：v1 一条 happy path 手工清单，不引入 Playwright
- **人工修正测试**：编辑 → 重提取 → 修正保持不被覆盖
