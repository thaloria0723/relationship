### 迭代记录(步骤 6 抓到并已整改,1 项)

1. **爆散火花 48 → 96(违反 R4)**:光点池扩容到 96 后,爆散段未钳槽位 → 炸裂后火花
   密度翻倍(`t2.15` 证据帧与上一轮同帧对照肉眼可辨)。整改:`spark(i)` 在爆散段
   `i ≥ SPARK_COUNT(48)` 恒 null + 单测守护;重取帧后均值回到 104.60 vs 104.52 ✅。
2. **漩涡在静帧里读作「一圈珠子」**(非缺陷,是调参):抵达窗太窄 → 同一时刻各点半径
   几乎相同。整改:抵达窗放宽到 `0.92–1.22`、旋臂宽度 `dθ×0.7`、盘面散布 `dr×1.8`、
   扭转角 2.6 → 3.4 rad —— 静帧里旋臂连成螺线(特写序列可辨)。

## 3. 实施与方案的偏差(以代码为准)

1. **`flash` 通道未接线**:方案曾写「溃散/凝聚各一记 flash」,实施前查证 `viewer.ts`
   只声明 `flash` 字段、**无处消费**(既有死通道)→ 不写死值;「亮起」由光点自身
   (珠光 + bloom)与既有压暗/增辉承担。要真接线 = 动液滴 shader、影响所有模式,另开。
2. **删滴是「逐颗即时」而非「汇聚末一把删」**(方案 §3.1 已按此设计):否则水底软影
   会留在空位(= 死亡退场踩过的「滴没了影子还在」)。
3. **光点起飞点取实时引擎位**(液滴随波微漂):`dropletFx` 每帧写 `liveX/liveY` 缓存,
   `spark` 读缓存(同步顺序保证先滴后光点);源滴被删后缓存保留最后值。

## 4. 已知边界与遗留

1. **编排与物理解耦(延续)**:光点是渲染侧池,水面不被漩涡搅动;删滴处会留下
   **水坑回弹的暗斑**(0.5–1s 内消退,证据帧 `t0.50/0.75` 可见)——是「滴离水回弹」的
   自然读感,非缺陷;若要更干净需引擎级「退场不留坑」,另议。
2. **直播运动质量仍未被「录屏」验证**:步骤 6 用「漩涡序列静帧 + 运动学单测」佐证,
   强于上一轮的纯冻结帧,但**不是录屏**;委托方实况观看为准(上轮不满意的正是直播态)。
3. `flash` 通道未接线(§3-1);**A-2 粗细映射 / 副本去留 / 夜闪回灌 / 文字两边界**
   等既有未尽事项原样有效(见交接 §8)。
4. 大转折在直播态首次进入时,旧网落定 ≈0.3s 与 t=0 的预兆段仍略重叠(既有边界,
   较整改前更轻:溃散从 0.16s 起、第一次删滴在 0.42s)。
